## 読みかた

再現はコマンド一本。手で数えると見落とすし、直すたびに数えなおすので
道具にしてある（`scripts/warnings.sh` と同じ位置づけ）。

```sh
python3 scripts/globals.py          # 区分ごとの集計（下の表）
python3 scripts/globals.py --full   # 112 個すべての一覧（付録）
python3 scripts/globals.py --check  # 分類の網羅性だけ確認（CI 向け）
```

数えているもの:

| 列 | 意味 |
| --- | --- |
| 参照 | `src/*.c` に名前が現れる回数（定義そのものを含む） |
| 書き | 代入・`++`・`--`・`strcpy` 系の第 1 引数に渡る形 |
| 別名 | `&x` や、配列名を裸で関数に渡す形の回数 |

「書き」からは 2 種類を除いてある。定義の置き場（`variable.c` `player.c`
`tables.c` `treasure.c` `monsters.c`）の初期値つき定義と、`game_state.c` の
`state->x = x`（状態の写しとりで `x` 自身は書かない）。どちらも数えると
「どこから状態が変えられるか」が見えなくなる。

**「書き」は下まわる見積り**であって正確な数ではない。局所ポインタ経由の
書きこみが数えられないため。たとえば `store` は

```c
store_type *s_ptr = &store[store_num];   // ← ここは「別名」として数える
s_ptr->store_ctr++;                      // ← この書きこみは数えられない
```

の形をとるので、`store` の「書き」は 0 だが実際には書かれている。
だから別名の列を併記している。**別名がとられている変数は「書き」を
信用してはいけない**という合図として読む。カプセル化で厄介なのもここで、
参照を機械的に置きかえるだけでは足りない箇所にあたる。
