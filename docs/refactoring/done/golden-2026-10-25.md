8 本の台本で本体の行の 44.5%（7005 / 15750。gcov）を通る。最初の 3 本では 28.6%。
どの行も通らないのは 110 本のうち 15 本（うち 7 本は表・ncurses・登録の結線・
`view_observer`）。

### 確かめ

- どの台本も 2 度走らせて記録と一致する。
- 壊して赤：階の生成の定数（dungeon）、状態行の文言（全部）、モンスターの一撃の判定
  （dungeon）、落とす・満腹の文言（items）、倒したときの文言・識別の問い（commands）、店の
  文言と値段の割り算（store）、掘る文言（terrain）、入力の終わりの手の登録と枝（input_end）。
- 素通り：持ち物が空のときの文言（その道を通らない）、セーブの記憶の添字（画面に出ない。
  `savefile_layout_test` が守る）。

### #84 で確かめきれなかったことを閉じた

#84-3 の入力の終わりの道は、`script(1)` が EOF を渡さないので実物で通せなかった（所見 67）。
#84 の前の `89ca18a` に同じ backend を組み、input_end の 1 つめ（歩いたあとで入力が終わる）と
3 つめ（種族の問いで入力が終わる）の起動を比べた：画面のハッシュ・終了の状態・保存の大きさが
今と一致。

### 分かったこと

- 最初の EOF で主ループが抜け、`app/main.c` が「end of input: saved」で保存して終える。
  `input_end_handling.c` の disturb とパニックセーブの枝は、1 つのコマンドの中で EOF を何度も
  読む場合のためのもので、台本では通っていない。
- `makefile.test` の `LIB_EXCLUDE` は #87 から効いていない（第 6 節）。

## #96 handle と iterator を 1 つに（ユーザーの依頼）

iterator の指す先が handle で、要素から handle へ戻す 2 段の参照になっていた。iterator を
表の添字を持つ構造体にして handle と 1 つの型 `creature_iterator` にまとめ、巡回と参照の両方を
持たせた（ユーザーの判断：数のままにせず、値の型ごとに専用の構造体にして型の検査を効かせる）。

| コミット | 何をしたか |
|---|---|
| `13483c9` | 正順・逆順の iterator を添字の構造体に。`at`・`index`・`from_reverse` を足す。テスト 4 件 |
| `10f6d90` | `creature_handle` → `creature_iterator`、`monster_get_creature` → `monster_creature_get`、`monster_make_creature_handle` → `monster_creature_at`（27 ファイルを道具で） |
| `2a024e6` | `monster_get_creature_handle` を消す（save.c・summon_undead・recall.c の `roff_recall` は iterator を受ける） |
| `416b092` | 添字に触るのを monsters.c だけに。save.c は局所に読んでから `at`。`scripts/check.sh` が見る |

各段で全関数の機械語を比べた。違いは手を入れた関数と、呼び先の名前・引数の型の切りつめ
（16 ビットへの切りつめが呼び手から呼び先へ）だけ。`creature_iterator_test` の、期待値も
`at()` を通って空回りしていた 1 件は、表の名前と並びで確かめる形に替えた。
攻撃の `attack_handle` は同じ形の handle だが、手を付けていない。
