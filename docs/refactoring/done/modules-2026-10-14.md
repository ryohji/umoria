# モジュール化（#80〜#88・#13・#75・#76）の経過

2026-10-14 の列。ユーザーの方針：ライブラリーを 1 つにしていたのを、循環参照しないように
分け、公開ヘッダと内部ヘッダを分けて、モジュールの役割を明確にする。それまでに済ませた
形（名詞で分けたディレクトリー #53、1 問 1 module #76、`externs.h` を include する #61、
層の規則は core/ だけ）は、必要なら戻してよいとされた。

## 0. 測ってから決めたこと

`layer_deps.py` の辺（1158 本・148 単位）から強連結成分を求めると、**47 単位が 1 つの
ループ**に入っていた。末端のはずの `io`・`desc`・`floor_items`・`monster_list`・
`hit_rolls`・`geometry` まで含む。名詞のディレクトリー（player/・item/・dungeon/…）の
どれも「状態」と「操作・コマンド」を同居させていて、名詞ごとのライブラリーはどう分けても
ループが残る。

単位を**役割**で並べなおすと、逆向きの辺は 26 本に減り、4 つの塊に集まった。

1. 端末と OS が上の層を呼ぶ（入力の終わりのパニックセーブ、`handle_pending_signals`）。
   台帳の #75・#13。
2. 端末の層が設定の global を読む。
3. model が world を呼ぶ（`invcopy`・`is_a_vowel`）。
4. world が command を呼ぶ（`get_item` ほか、罠の中の `enter_store`）。

ユーザーの判断：層は core < model < platform < ui < world < command < app（「term」は
GUI への移行も見て `ui` と名づけた）。ディレクトリーを層に合わせて組みなおす。公開
ヘッダをまとめ、.c も切りのいい単位でまとめ、多量の注釈は要点だけにして文書へ移す。
繰りかえしの実装はマクロで整理する。#75・#13 も着手する。

## 2. 確かめかた

- **全関数の機械語の比較**（`scripts/cmp_all.sh`）。基準のコミットと作業木を
  `-O2 -fno-inline -fno-ipa-ra` で組み、共通の全関数を `dis_compare.py` で比べる。
  違いが記号名の注釈だけなら「same except symbol comments」（static の改名）。
- **データの (種類, 大きさ) の多重集合**（`scripts/check_statics.sh`）。同名のファイル
  static を 1 つの翻訳単位に連結すると、C の仮定義で 1 つの変数になる（所見 63）。
  #85-4 の最初の連結で 42 → 41 になって見つかった。
- **注釈だけの変更**は `scripts/comments_only.sh`（`gcc -fpreprocessed` で注釈を除いた字面）。
- 連結は `scripts/merge_modules.py`（字を変えずにつなぎ、重なる static を改名する）。

許した違いは 3 種：static の改名による記号名、中身が同じ関数のたたみの入れかわり
（所見 64）、意図した変更（登録する手の呼び出し、`signal` の呼び先、`get_item` の
`confirm_item`）。

## 3. 担当の報告と実際

実装は Sonnet 5.5・Haiku 5.5 の担当に分けて並行に進めた。報告をそのまま信じず、統括が
`cmp_all.sh` と第 2 節の 1〜4 を測りなおした。食いちがったもの：

- #88-2・#88-3：「1826 件 GREEN」とあったが、テストの組みたてが `movement_rate_test` の
  multiple definition で止まり、9 本しか組まれていなかった。#88-5 で足場を外して直した。
- #88-3：「警告 0」とあったが、`app/game_state.c` から dungeon のヘッダを消したまま足して
  おらず、暗黙の宣言で返り値のポインタが int に切りつめられていた（警告 12 件）。#88-4。
- #83-2 の本文の「テスト（pending）」、#85-1・#85-2 の本文には機械語の比較が無い。統括が
  比べ、一致を確かめた（#85-1・#85-2 は全関数が static の名前の違いだけ）。
- #87：「層の規則を自動で強制する」は言いすぎで、止まるのは相手の `.o` がまだ引かれて
  いないときだけ。#87-4 で注釈を直した（所見 68）。
- #85 の最初の担当は、統合を「書きなおし」で進めて build を壊したので、未コミットの分を
  捨て、機械的な連結に切りかえた。
- #13 の担当は `signals()` で SIGTSTP を戻すように変えた（ふるまいの変更）。捨てて
  統括が作りなおした。担当の気づいた「保存のあと ^Z が効かない」は既知の B15。
- #84 の担当は #13 の段を残して止まった。

赤いままのコミット（履歴は書きかえていない）：#88-2・#88-3・#88-4（テストの組みたてが
止まる。直したのは #88-5）、#88-3（警告 12 件。直したのは #88-4）。マージの前に
`develop..integrate/modules` の 43 コミットを 1 つずつ空から組んで第 2 節の 1〜3 を
走らせ、この 3 つのほかはどれも警告 0・1826 件 87 本 GREEN・globals OK・層 OK だった。
