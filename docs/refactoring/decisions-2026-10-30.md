# 判断待ちの項目と、決めるのに要る事実（2026-10-30）

台帳（`REFACTORING_PLAN.md`）の「前提・判断」の列に **判断** と書いた項目を、1 つずつ
「何を決めるか・選べる道・事実・待つと何が起きるか・勧め」で並べた。数はこの日に測った。
並びは、決めるのを遅らせたときの手戻りが大きい順。

## 1. #31 座標の型を入れるか

- **決めること：** `(int y, int x)` の組を 1 つの型（たとえば `typedef struct { int y, x; } Coord;`）に
  するか。
- **事実：** 本体で `(…int y, int x…)` を受ける定義が 19 ファイル・70 本、`int *y, int *x` を
  出力に持つ所が 6 か所。core/ の `distance(int y1, int x1, int y2, int x2)` が根。座標の型は
  まだどこにも無い。守りは golden の台本 11 本と総当たり 6 本（機械語が変わるので
  `cmp_all.sh` は使えない）。
- **選べる道：**
  - (a) 入れる。core/ の幾何（`distance`・`mmove`・`in_bounds`・`los`）から始めて、層を上へ
    1 ファイルずつ。値で渡す（2 つの int なのでコストは同じ）。
  - (b) 入れない。行を閉じる。
- **待つと：** 関数を出すたびに `(int y, int x)` の定義が増える（この日の `bolt_to_next_creature`
  も `int *y, int *x` を持つ）。総当たりの道具も座標を組で書いている。(a) にするなら早いほど
  安い。
- **勧め：** 決めるだけ先に。入れるなら #98 の前か同時（段を動かす関数の引数がそこで変わる）。

## 2. #98 world/ の行動の段のループ

- **決めること：** 行動の段の中のループを切るか、切るなら関数をどの段に置くか。
- **事実：** 行動の段の 11 単位のうち 8 つ（creature・monster_melee・projectiles・spells・traps・
  terrain_commands・player_move・run_path）が 1 つの強連結成分。creature.c へ戻る辺は 3 本で、
  中身は 2 種類だけ：
  - 見え方の更新：projectiles → `update_mon`、spells → `update_mon`・`creatures(false)`、
    player_move → `creatures(false)`（`creatures(false)` はモンスターを動かさず、見え方だけ直す）
  - 増殖：spells → `multiply_monster`
  
  ほかに run_path ⇄ player_move、traps ⇄ player_move（罠で飛ばされると `move_char`）。
- **選べる道：**
  - (a) 見え方の更新（`update_mon` と `creatures(false)` の中身）を表示の段の新しい単位へ、
    `multiply_monster` を床と生死の段へ。creature.c へ戻る辺が無くなり、大きなループは解ける。
    プレイヤーの移動の 3 つ（player_move・run_path・traps）の小さなループは残る。
  - (b) (a) に加えて、プレイヤーの移動の 3 つを 1 単位にまとめるか、段を分ける。
  - (c) 段の中のループは許す（いまのまま。`WORLD_TIERS` は段のあいだしか見ていない）。
- **待つと：** 行動の段で関数を出すたびに、ループの中の辺が増えうる。`layer_deps.py` は段の中を
  見ないので、増えても気づかない。
- **勧め：** (a)。動かすのは関数の置き場だけで、機械語は同じにできる（`cmp_all.sh` で守れる）。
  `update_mon` が表示の段より上を呼ばないかは、動かす前に確かめる。

## 3. 直すバグ候補を選ぶか（F）

- **決めること：** `bugs.md` の候補のうち、どれを直すか（直さないなら、ふるまいとして記録のまま）。
- **事実：** golden の記録に、いまのふるまいとして入っているのは 6 つ。
  - B24：光る手の混乱に抵抗したとき「The orcis unaffected.」（空白が抜ける）
  - B30：足もとに物があると、Create Food の巻物が何もせずに消える
  - B31：店に入って売る問いを取りけすと、入った 1 歩が turn を使わない
  - B32：rogue-like の組で ^J は回数を受けるが ^M は受けない
  - B33：原文の鍵の組で Enter・^J が +（wizard では経験値を倍に）
  - B34：飛ぶ呪文のうち teleport と poly だけ、最初のモンスターで止まらない
  
  ほかは B35（下の 4）・B5・B6（魔法道具の成功率）など。どれも上流の意図か確かめていない。
- **待つと：** 直すたびに golden の記録を作りなおす。記録は台本 11 本と総当たり 6 本に広がって
  きたので、直すのがあとになるほど、作りなおす記録が増える。逆に、リファクタリングの途中で
  直すと「ふるまいを変えない」の確かめが効かなくなるので、直すなら独立のコミットで。
- **勧め：** 直すと決めたものだけ、1 つずつ「直す・記録を作りなおす」の 2 コミットで。迷うものは
  記録のまま。B24 は文字列の空白 1 つで、#51 と一緒に決められる。

## 4. #27 残りの鎧の巻物 3 つと B35

- **決めること：** `read_scroll` の case 3・35・36 をどう出すか。B35 を直すかに絡む。
- **事実：** `read_scroll` は 328 行。この switch では `i_ptr` が case の作業用の変数で、鎧の 3 つは
  塊の奥で条件つきで `i_ptr` を装備に指しなおす。鑑定の case（4）は、`i_ptr` が読んだ巻物を
  指し、その旗がちょうど `0x00000008` であることを当てにして、`item_val` を下げて巻物を探す
  （B35）。表の巻物は bit が 1 つなので起きない。wizard の `@` で bit を 2 つ持つ巻物を作れば
  起きうる（試していない）。
- **選べる道：**
  - (a) いまの流れを保つ：鎧の 3 つを、指しなおした `i_ptr` を返す関数にする
    （`i_ptr = enchant_armour(i_ptr, &ident);` のような形）。字のまま出せて、B35 は残る。
  - (b) B35 を直す：鑑定の case は巻物の `item_val` から改めて引く。`i_ptr` は case の局所に
    なり、鎧の 3 つは武器の 4 つと同じ形で出せる。ふるまいが変わるのは bit を 2 つ持つ巻物
    だけ（表の巻物では変わらない）。
- **待つと：** 手戻りは小さい。ほかの作業と絡まない。
- **勧め：** (b) を先に決められるなら (b)。迷うなら (a) でも後から (b) に移れる。

## 5. #51 光る手の 2 か所（と B24）

- **決めること：** モンスターの攻撃（`make_attack`）とプレイヤーの攻撃（`player_melee`）の、光る手の
  約 18 行を 1 つにするか。するなら、違いのどちらを正とするか。
- **事実：** 違いは 6 つ。
  1. 前者だけ `adesc != 99` を見る（意図がコメントにある）
  2. 名前の大文字化の手が違う（出る文は同じ）
  3. 記憶を足す条件：`visible && !player_is_dead()` か `m_ptr->ml` か
  4. 「Your hands stop glowing.」と `player_glowing_hands_spend()` の順が逆（見分けられないと
     読めるが、確かめていない）
  5. 混乱に抵抗するかの判定：前者は乱数を先に引き、後者は眠らない相手には乱数を引かない
     （畳むと乱数の並びが変わる）
  6. 前者の「is unaffected.」は頭の空白が無い（B24）

  golden の台本 `glowing_hands` が両方の枝を守っている。`make_attack` は #25 で光る手の塊を
  残して割ったので、どちらに決めても #25 の仕事は無駄にならない。
- **選べる道：** (a) 畳む。3・5・6 のそれぞれでどちらを正とするかを決める（ふるまいが変わる所は
  記録を作りなおす）。(b) 畳まない（記録のみ）。
- **待つと：** 手戻りは無い。
- **勧め：** 急がない。決めるなら B24 と一緒に。

## 6. #28 `cast` と `pray` を 1 つの骨格に

- **待つと：** 手戻りは無い。(b) は (a) の前段にもなる。
