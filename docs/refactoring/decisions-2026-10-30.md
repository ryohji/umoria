## 1. #31 座標の型を入れるか

- **決めること：** `(int y, int x)` の組を 1 つの型（たとえば `typedef struct { int y, x; } Coord;`）に
  するか。
- **事実：** 本体で `(…int y, int x…)` を受ける定義が 19 ファイル・70 本、`int *y, int *x` を
  出力に持つ所が 6 か所。core/ の `distance(int y1, int x1, int y2, int x2)` が根。座標の型は
  まだどこにも無い。守りは golden の台本 11 本と総当たり 6 本（機械語が変わるので
  `cmp_all.sh` は使えない）。
- **選べる道：**
  - (a) 入れる。core/ の幾何（`distance`・`mmove`・`in_bounds`・`los`）から始めて、層を上へ
    1 ファイルずつ。値で渡す（2 つの int なのでコストは同じ）。
  - (b) 入れない。行を閉じる。
- **待つと：** 関数を出すたびに `(int y, int x)` の定義が増える（この日の `bolt_to_next_creature`
  も `int *y, int *x` を持つ）。総当たりの道具も座標を組で書いている。(a) にするなら早いほど
  安い。
- **勧め：** 決めるだけ先に。入れるなら #98 の前か同時（段を動かす関数の引数がそこで変わる）。

## 4. #27 残りの鎧の巻物 3 つと B35

- **勧め：** (b) を先に決められるなら (b)。迷うなら (a) でも後から (b) に移れる。

### #72 の残り：inven_command の「持ちなおす状態」に要る情報（判断 4 の材料）

inven_command（command/inven_menu.c、485 行）は、持ち物の画面のコマンド（着る・外す・落とす・
持ちかえ・一覧）を受ける。turn を使うと**いったん帰り、次の turn に同じ画面から再開する**
（呼び手は app/dungeon.c と command/store_ui.c）。再開とそのあいだの画面のために持っている
状態は、置き場ごとに 3 つに分かれる。

**1. 呼びだしをまたいで持つ（ファイルの static、5 個）**

| 名前 | 中身 | 書く所 |
|---|---|---|
| `scr_state` | いま出している画面（空・装備・持ち物・着られる品・help・不正） | inven_screen、再開の頭、inven_command の頭（BLANK） |
| `scr_left`・`scr_base` | 画面の左端と下端（表を描いた幅と行） | inven_screen、x の装備の描きなおし、再開の頭 |
| `wear_low`・`wear_high` | 持ち物のうち着られる品の範囲 | `w` の頭で数える。wear_item（品が減ると狭め、外した品が戻ると広げる） |

**2. ほかの module が持つ（窓口越し）**

- 再開するコマンドの文字：`pending_inven_command()`・`suspend_inven_command()`・
  `finish_inven_command()`（ui/input_state.c）
- 帰ったあいだに画面が流されたか：`screen_was_flushed()`（ui/screen_touched.c）。流されて
  いたら「Continuing with inventory command?」と訊く

**3. 1 回の呼びだしの中だけ（局所。段をまたいで書きかわる）**

| 名前 | 中身 | 書きかわる所 |
|---|---|---|
| `command` | いまのコマンドの文字 | 落とす `d` ⇄ 装備から落とす `r`（`/` で入れかえ、装備しか無ければ `r`）、外せないとき `t` → `r`、終わりに ESC |
| `selecting` | 品を選んでいる最中か | コマンドの switch が立て、選ぶループが下ろす（空白、落としたあと、範囲が空） |
| `took_turn` | turn を使ったか | 持ちかえ・外す・着る・落とす |
| `which` | 選ぶループで読んだキー | ESC で終わり、`*`・空白で画面、`/` で入れかえ、文字・大文字（確かめる）・数字（刻みで選ぶ） |
| `item`・`slot` | 選んだ品と、着る先の枠 | 文字 → 位置、装備の何番め → 枠（`t`・`r`）、品の種類 → 枠（指輪は左右を訊く） |

**分けるときの段と、段をまたぐもの**

1. 再開か新しいかの頭（scr_* を整える）
2. コマンドの switch（`command`・`selecting`・画面・着られる範囲を決める。持ちかえはここで
   turn を使う）
3. 選ぶループ：問いの文（範囲・言いまわし・入れかえの案内は `command` と数から決まる）→
   キー → 品か画面の操作か → コマンドごとの行い（外す／落とす、着る（枠を決める）、落とす（数を
   訊く））
4. 終わりかた：ESC で抜ける／turn を使ったら再開の文字を預けて帰る／次のコマンドを訊く

段をまたいで書きかわるのは `command`・`selecting`・`took_turn`・`which` の 4 つ。案は、この 4 つを
1 回の呼びだしの構造体（たとえば `inven_session`）にまとめて段の関数に渡し、ファイルの static の
5 つは画面の構造体 1 つ（static 1 個）にまとめる形。純粋に出せる塊もある：品の種類 → 着る枠
（指輪の問いを除く）、装備の何番め → 枠（wear_item の逆向きの数えと対）。

**決めること：** (a) 構造体を 2 つ（1 回の呼びだしと、画面）にするか、static はそのままで
1 回の呼びだしの 4 つだけを構造体にするか。(b) 段の関数の分けかた（上の 4 段か、コマンドごとか）。

### 訊いていること（2026-10-31）

1. **B34（飛ぶ呪文のうち teleport と poly が最初のモンスターで止まらない）を直すか。**
   `teleport_monster` の上の注釈は上流のもので「Teleport all creatures in a given direction away
   -RAK-」とあり、線の上を全部飛ばすのは意図と読める。poly の「抵抗されたら次へ」の注釈は
   #19 で足したもので、意図は分からない。案：teleport は意図どおりとして閉じ、poly だけ直すか、
   どちらも閉じるか。
2. **#51（光る手）の違い 3・5 のどちらを正とするか。** 3：記憶を足す条件
   （モンスターの攻撃では `visible && !player_is_dead()`、プレイヤーの攻撃では `m_ptr->ml`）。
   5：混乱に抵抗するかの判定（モンスターの攻撃では乱数を先に引き、プレイヤーの攻撃では眠らない
   相手には引かない）。6（B24）は直した。
3. **#31 の着手の順。** 案：(1) core/ に `coordinate`（`int row, column`）を置き、`distance` を
   `coordinate` 2 つを受ける形に替える（呼び手 17 か所は `(coordinate){y, x}` で包む）→ (2) プレイヤー
   の位置の窓口（`player_row()`・`player_col()`）に `player_position()` を足して呼び手を順に →
   (3) 幾何（`in_bounds`・`los`・`mmove`）→ (4) モンスターの位置（`fy`・`fx`。セーブの並びは
   変えない）→ (5) 向き。包む段（1）は一時的に字が長くなる。逆に、プレイヤーの位置から始めて、
   `distance` は呼び手の多くが `coordinate` を持ってから替える道もある。
